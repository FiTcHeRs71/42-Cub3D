● Mouvement fluide — le principe                                                                         
                                                                                                       
  Problème avec mlx_key_hook                                                                             
   
  mlx_key_hook tire une seule fois par appui. Si tu bouges dedans, le joueur avance d'un coup puis       
  s'arrête. Pour un mouvement fluide il faut un état des touches.
                                                                                                         
  Étape 1 — Ajouter l'état des touches dans t_data          

  // dans t_data (cub3d_struct.h)
  bool    keys[256];                                                                                     
                                                                                                         
  Étape 2 — Deux hooks séparés press/release                                                             
                                                                                                         
  Dans init_window, remplace mlx_key_hook par deux hooks :                                               
  mlx_hook(mlx->mlx_window, 2, 0, key_press, data);    // event 2 = touche enfoncée
  mlx_hook(mlx->mlx_window, 3, 0, key_release, data);  // event 3 = touche relâchée                      
                                                                                                         
  key_press → data->keys[keycode] = true                                                                 
  key_release → data->keys[keycode] = false                                                              
  ESC dans key_press → close_window                                                                      
                                                                                                         
  Étape 3 — Problème structural à régler d'abord            
                                                                                                         
  La position/direction du joueur (pos_x, pos_y, dir_x, dir_y, plane_x, plane_y) vit actuellement dans un
   t_raycast local à raycasting(). Elle est réinitialisée à chaque frame → impossible de bouger.
                                                                                                         
  Il faut déplacer ces 6 champs dans t_data (ou une t_player dans t_data) pour qu'ils persistent entre   
  les frames.
                                                                                                         
  Étape 4 — Dans game_loop à chaque frame                                                                
  
  si keys[W]  → avancer  : pos_x += dir_x * speed (si pas de mur)                                        
  si keys[S]  → reculer  : pos_x -= dir_x * speed (si pas de mur)                                        
  si keys[A]  → strafe G : pos_x += plane_x * speed (si pas de mur)  // perpendiculaire                  
  si keys[D]  → strafe D : pos_x -= plane_x * speed (si pas de mur)                                      
  si keys[←]  → rotation gauche : matrice 2D sur dir + plane                                             
  si keys[→]  → rotation droite : matrice 2D sur dir + plane                                             
                                                                                                         
  Collision                                                                                              
                                                                                                         
  Avant de bouger, vérifie séparément X et Y :              
  si map[(int)(new_x)][(int)(pos_y)] != '1' → autorise le déplacement en X
  si map[(int)(pos_x)][(int)(new_y)] != '1' → autorise le déplacement en Y
  Ça permet de glisser le long des murs au lieu de bloquer complètement.                                 
                                                                                                         
  Rotation — matrice 2D                                                                                  
                                                                                                         
  new_dir_x   =  dir_x * cos(rot) - dir_y * sin(rot)                                                     
  new_dir_y   =  dir_x * sin(rot) + dir_y * cos(rot)        
  new_plane_x = plane_x * cos(rot) - plane_y * sin(rot)                                                  
  new_plane_y = plane_x * sin(rot) + plane_y * cos(rot)     
  rot = environ 0.03 radians. Négatif pour gauche, positif pour droite.

  pour qu'il initialise t_data plutôt qu'un t_raycast local. Ça débloque tout le reste.
